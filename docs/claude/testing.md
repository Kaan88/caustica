# Build, run, test and measure

Moved out of `CLAUDE.md` on 2026-11-02 (unchanged text). Paths are relative to the repo root. Where this file says "see X", X is a section of `docs/engine-notes.md`.

## Build, run, verify

```powershell
$env:CARGO_TARGET_DIR="target/validation"   # keep checks away from target/release (the launcher's exe)
cargo fmt --check; cargo test --locked; cargo clippy --locked -- -D warnings; cargo build --locked
```

- `launch.cmd` starts `target/release/caustica.exe` and only builds it if it is missing. It never rebuilds a stale exe.
- Release builds use `lto = "thin"` and `codegen-units = 1`, so they are slow.
- **Release is a GUI-subsystem exe with no console output.** Debug builds have a console.
  - `tools/verify.ps1` runs release via `Start-Process` with stdout and stderr redirected.
- `build.rs` does the following:
  - Asserts that `vendor/dlss`, `vendor/fsr` and `vendor/xess` exist.
  - Compiles 14 shader entries: `trace`, `restir_presample`, `restir_initial`, `restir_spatial`, `filter`, `display` and `glare` (entry `glare_pass`, track 16) as cs_6_5; `vs_main` and `ps_main` as 6_0. `trace` is built four times: plain, `trace_maps` (`-D TEXTURE_MAPS`), `trace_paths` (plus `-D PATH_RECORD`, the path visualizer) and `trace_lpe` (plus `-D LPE`, light path expressions). The three ReSTIR DI passes come from the same file with `-D TEXTURE_MAPS`. Track 15's integrators come from `integrators.hlsl` (which includes pathtrace.hlsl), also with `-D TEXTURE_MAPS`: `bdpt`, `bdpt_resolve`, `photon_clear`, `photon_trace`, `photon_gather`.
  - Compiles the bridge and links `nvsdk_ngx_d`.
  - **Copies `nvngx_dlss.dll` and `nvngx_dlssd.dll` next to the exe.** A running instance locks them and the build fails. Use a separate `CARGO_TARGET_DIR`, and never kill the user's running app.
- Headless runs need a real GPU and use a hidden window:
  - Command: `caustica.exe --headless --frames N [--width W --height H --scale s --spp n --samples cap --preset 0..23 --settings f.json --scene name --rr|--no-rr|--require-rr --raw (denoiser aliases, last wins) --debug] --capture out.png|out.exr`.
  - Success prints `RENDER_OK frames= samples= gpu_ms= rr= size= gpu_ms_mean= frame_ms_mean= fence_wait_ms_mean= trace_ms_mean= reconstruct_ms_mean= display_ms_mean= ui_ms_mean= meter_ev= exposure=` (`meter_ev` the settled metered EV without bias, `none` in manual; `exposure` the final linear exposure) (reconstruct is RR, or the native filter with `--no-rr`). `tools/perf_baseline.ps1` is the track 20a sweep. The means are taken from frame 10 on, so use ≥ 200 frames with `--no-vsync` for benchmarks. A `--headless` run acquires and presents no swap chain image (Vulkan draws the display pass and the UI into an offscreen image of the swap chain's format and size; D3D12 skips `Present`), so no compositor or monitor rate throttles it: `frame_ms_mean` is the CPU-side frame including the fence wait, and it approaches `gpu_ms_mean` when the GPU is the bound (before this, Wayland floored it at the monitor's refresh period, 6.94 ms at 144 Hz, even with `--no-vsync`). A windowed run still paces on Present. On a Wayland desktop with XWayland, a hidden run that draws no interface uses X11, so it gets no taskbar entry (engine-notes "Hidden runs on X11 under Wayland"); unset `DISPLAY` to keep it on Wayland.
  - `--preset`/`--settings` (only one) is applied before all other switches, so order doesn't matter.
    - **Old builds (including `main` before 2026-10-29's fixes) applied them in order**, so `--raw` and `--spp` given before `--preset` were silently reset. Put `--preset` first when benchmarking an old exe.
- Other test modes:
  - Self-update: `--update-from <file|URL>` (with `SHA256SUMS` beside it), `--update-yes`, `--update-cancel-at <bytes>` (engine-notes "Self-update"). Linux needs a real AppImage from `tools/appimage.sh`, which needs `scenes/models`, `hdri` and `textures` to exist.
  - Vulkan: `--vulkan` (Windows) renders with the Vulkan backend (the whole renderer, upscalers included; compare its EXR with D3D12's as engine-notes "Vulkan backend: design" phases 3–6 did); `--vulkan-smoke [--headless] [--frames N]` checks device, swap chain and readback alone. Linux (VM `caustica-vm`, lavapipe): `xvfb-run -a caustica --headless …`, `--debug` turns on the validation layer.
  - `--self-test`: 308 scripted frames (`SCENES_FROM`), then one frame per scene file (176 files in the built-in, generated, mesh, environment, materials and puzzle packs, 484 frames in all); implies headless and `--debug`. It fails on any D3D12 warning.
    - Frames 10–125 cycle all 24 presets; frames 130–140 make live edits (lights, all shapes, emission, hide, delete, pick, frame, randomize); 285–287 run BDPT, photon mapping and battle mode on preset 3 and check the image and every quadrant. 286–289 run with `spectral` on (photon mapping through glass with dispersion, battle mode, the Double Gauss lens with dispersion); 290 turns it off again. 292–293 grab a ball with physics on (a gizmo handle under the pointer wins). 294–295 run BDPT spectral, then RGB (the spectral twin once hung the RGB one after it); 296 returns to the path tracer. 297–299 turn the shadow catcher and ground projection on, check the image, and turn them off. 300–302 do the same for heterogeneous fog. 169–172 start the CPU reference in the viewport, wait for its first pass, and check it reached the A/B reference texture (or that an unsupported scene was refused). 248–251 walk with the flashlight on and a hidden light that casts no shadows. Frame 282 also applies the Accurate quality bundle to a copy of the settings and checks it validates and is recognised. Frames 241–242 open the command palette, run a setting entry (it must change the tab and selection) and close it. 240 and 245 run with the exposure meter on (E7): 240 checks that auto exposure puts the image's metered luminance at middle grey (the CPU `meter_reading` of the linear output against the GPU's state, within 0.15 stop), 245 lights the Cornell box at 1e-7 (`light_intensity = 12e-7`, the default 12 scaled) and checks that the Eyes look leaves the 8-bit output with no more red than blue while the linear output has red pixels. Every other frame ends with `auto_exposure` and `eyes` forced off (the pin at the end of `self_test_script`: presets and scene files default to both on), so no image check depends on the meter. 250 is free.
    - Frame 127 (the night sky) also asserts the catalogue's stars are on the GPU (`stars_loaded`, night sky N3).
    - Every frame it asserts that the GPU triangle and emitter counts match the settings.
    - The script lives in `src/selftest.rs`: `self_test_script` (edits, before rendering) and `self_test_checks` (asserts, after rendering), both called from `redraw()`. Add new edits on unused frame numbers.
  - Frames 303–307 run the software view: the linear output must be the CPU's image bit for bit, and the saved EXR the same image, the GPU must stop after its pass, and a camera move must restart it.
  - `--cpu`: starts in the software view. With `--headless --frames N` a run waits for the CPU's `--samples` before it captures, and prints `CPU_VIEW samples= seconds= threads= images= missing=`; `--orbit-test` doesn't wait, so `images` tells how many previews kept up.
  - `--debug`: needs the Windows Graphics Tools.
  - `--orbit-test`: moves the camera 0.25° per frame after frame 64.
  - `--walk`: starts in walk mode at the given camera (the walker stands an eye height, 0.62, under it; with the camera 0.62 above the floor it does not move). The walk avatar (engine-notes "Walk avatar") is drawn when `walk_avatar` is on (the default; `--set walk_avatar=false` for the A/B). With `--reference` the CPU draws the standing avatar at the camera, so `tools/oracle.py` can compare a walk frame (`tools/oracle.py --walk`, always with the camera placed: `--set pitch=0 --set distance=0.9 --set 'target=[0,-0.38,0]'` for mirror-room, which gives GPU/CPU 0.989, z -1.23; without it the walker settles to the floor and the two sides draw different views). Walking itself needs input: headless frames show a standing pose (gait 0). Self-test frames 247–251 walk with the avatar on (frame 249 asserts its ten boxes and the one hidden head).
  - `--oidn` (or `--set still_denoise=true`): Intel OIDN on a PNG or JPEG `--capture` and on `--reference` PNG/JPEG output (never an EXR); prints `OIDN WxH N ms (albedo, normal)` to stderr, or `OIDN skipped:` / `OIDN unavailable:` with the reason when the library is not beside the exe. Pair it with `--raw`. The measurements and the harness are in engine-notes "OIDN for stills".
  - `--capture-sequence dir`: captures the last 32 frames.
  - `--ui-skin-sheet` (with `--capture-ui`): the skin's control sheet over the viewport, every control in rest, hover, pressed, focused and disabled plus a menu, a segment and an open combo (engine-notes "UI skin: Instrument"). Use 1600 × 900 so it fits. It is the only way to capture hover and pressed looks, since a headless run has no pointer.
  - `--ui-describe`: opens the Describe (text-to-scene) card for a capture. The timeline shows in any capture of a scene with keys (`--scene scenes/builtin/sunlit-room-day-cycle.json`).
- `--truth rows|all` (with `--reference`, or `--cpu`): the CPU reference's "truth" switch (`scene::Truth`, Settings field `truth`, Render tab → Advanced → CPU truth; engine-notes "CPU truth switch"). Each row turns one shortcut the CPU copies from the GPU into the exact computation: `roulette` (B1), `firefly` (B3), `floors` (B4), `collisions` (D1), `fog_cutoff` (D2), `absorption_floor` (D6), `sdf_march` (C3) have code; `glass_btdf` (A1), `internal_reflection` (A2), `multiscatter` (A3), `fresnel` (A4), `offsets` (C1), `shadow_terminator` (C2) are hooks that print `REFERENCE_TRUTH_PENDING`. All off is today's model, which keeps `tools/oracle.py` green. `tools/oracle.py --cpu-truth rows` renders the CPU side with them (the ratio is then the bias of the GPU's shortcut); `--cpu-set key=json` / `--gpu-set key=json` give one side a setting (e.g. `--gpu-set bounces=6 --cpu-set bounces=64` measures the truncation). The reference prints `dropped=` (NaN/Inf samples, row B4) on `REFERENCE_OK`; the oracle repeats it.
- `--time T`: the scene as it stands at T seconds on the timeline, frozen (`reference::at_time`: tracks, per-frame script, physics and cloth in fixed steps, the rotating camera), on either renderer. It makes a physics scene comparable between two runs; `tools/oracle.py --time T` passes it to both sides.
- `tools/lane_overlap.py [name=path[@base] ...]` (read-only, stdlib): diffs parallel lane worktrees against their bases and reports files touched by several lanes (hunk ranges, overlap or identical) and the special collisions: `cbuffer Frame` / `Constants` fields, `Settings` fields, shader ENTRIES, self-test frame numbers, shared docs. Defaults to the six lanes; run it before merging them.
- **Windows-side checks on Linux** (no Windows needed, merge gate; `docs/claude/d3d12-on-linux.md`). Both go through `target/safe.sh` (the cargo one takes the build lock):
  - `tools/check_dxil.py` compiles every DXIL entry in `build.rs` (parsed from it: the `entries` array and `dxil_command`) with `vendor/dxc-linux/bin/dxc` in parallel, validates each with `dxv` and prints a pass/fail table. Exit 1 on any failure. Output goes to `/home/kaan/caustica-tmp/d3d12check/dxil` (`--out`).
  - `tools/check_windows.sh [check] [cargo args, e.g. --all-targets]` runs `cargo check --locked --target x86_64-pc-windows-msvc` with the user-local official toolchain (see setup.md) and `CAUSTICA_CHECK_ONLY=1`, which makes `build.rs` write empty `.dxil` stubs and skip the vendor SDK asserts, `rc.exe`, the C++ bridges, the DLL copies and the link args. `CAUSTICA_CHECK_ONLY=dxil` compiles real DXIL with the Linux DXC instead (8 at a time). Its target dir is `target/wincheck`. No clippy for the Windows target: the official toolchain has no clippy component and the Arch `clippy-driver` can't read its std (E0514), so read the warnings it prints instead (the crate allows `dead_code` and `unused_imports` on non-Windows, `main.rs` line 5, so these show up only here).
  - What they prove: the `cfg(windows)` Rust type-checks against `windows` 0.62 (D3D12, the `src/gpu/**` backend, `platform.rs`, `display.rs`, `update.rs`), the shaders compile for SM 6.5 and 6.9 and pass the DXIL validator, and `include_bytes!` of every entry resolves. What they don't: linking, the C++ bridges (`bridge/ngx.cpp`, `fsr.cpp`, `xess.cpp`), `cargo test`, anything running (no D3D12 device, no debug layer, no self-test), and the Windows SDK's own dxc (the Linux one is the 1.9 release, so a shader could differ in principle).
- Unbiased reference for noise measurement: `--no-rr --raw --samples N --frames N/spp --capture ref.exr`. Linear RGB32F at output resolution.
- **Pin the display in every comparison (E7).** New scenes and presets default to auto exposure and the Eyes look, so a PNG depends on the meter. `tools/oracle.py`, `rr_stability.py` (its scene file), `motion_error.py`, `upscale_quality.py`, `native_aa.py` and `integrator_sweep.py` pass `--set auto_exposure=false --set eyes=false` (oracle puts it before the user's `--set`s, so `--set` can still override); the CPU display tests build their settings with `plain()` (exposure 1, auto exposure off, Eyes off). A hand-run PNG comparison needs the same flags, or compare linear EXRs (the exposure doesn't touch them).
- `tools/rr_stability.py` is an RR shimmer regression. It uses emission-only walls and black emission-only blocks, so there is no Monte Carlo noise.
  - Run `python tools/rr_stability.py --exe <path>` to use a build other than `target/release`.
  - Thresholds: edge temporal std < 0.02 and mean frame difference < 0.0015.
  - Last result, 2026-10-29: 0.0071 and 0.00017. The 2026-10-26 run is kept as `captures/rr-stability/regression/metrics-2026-10-26.json`.
- `--set key=json` overrides one top-level setting after `--preset` or `--settings`. Unknown keys are rejected. Example: `--set direct=0 --set indirect=1`.
- Python on Windows needs Windows paths. Use `cygpath -w` when calling it from the Bash tool.

## Measurement conventions

- Error metric: RMSE ×1000 on compressed luminance l/(1+l) against a high-spp reference. The reference used 16,384 spp.
- Also track a 5×5-blurred error, which catches ghosting that plain RMSE hides.
- Compare against an **independent** reference: a white-noise reference when testing Sobol.
- Use numpy on EXR captures. imageio has no EXR backend here, and OpenEXR and cv2 are not installed.
  - The exe writes **tiled (64×64), RLE-compressed** RGB float EXRs.
  - Use `tools/exr.py`: `exr.read(path)` returns an H×W×3 float32 array. It handles scanline or tiled files with NONE or RLE compression.
  - It was used to confirm that direct + indirect recompose the beauty to 2e-7 relative error (presets 0, 3, 8, 21; raw native path).
- Report in a table, with the sample count where each method reaches equal error.
